# Práctica Integradora 1 a 5

1. **Configuración Inicial:**
   - En una nueva carpeta, descargar los archivos de la práctica `frontend-practica`:
     ```bash
     npx degit cachac/testingLabs/assets/dev/frontend-practica frontend-practica
     cd frontend-practica
     ```
   - Instalar las dependencias:
     ```bash
     npm install
     ```
   - Verificar la comunicación correcta levantando el servidor de desarrollo y exponiéndolo a la red:
     ```bash
     npm run dev -- --host
     ```
     *(Abrir `http://<IP_PUBLICA_VM>:5173` en el navegador y hacer clic en "Fetch Data" para confirmar que carga)*.
    - **Detener** el servidor de desarrollo.
  	- Crear un nuevo repositorio de GitHub con el nombre `frontend-practica`.
		- Subir los archivos de la práctica al repositorio.
2. **Pruebas Unitarias:**
Para estas pruebas unitarias se usará la herramienta [Jest](https://jestjs.io/), sin embargo, el concepto es aplicable a cualquier herramienta o lenguaje.
   - Ejecutar las pruebas unitarias localmente con `npm run test`.
   - Existe una prueba que falla a propósito en `utils.test.js`.
   - (Opcional) Modificar la función en `utils.js` para corregir el error y volver a ejecutar `npm run test` para verificar el resultado.
   - (Opcional) Asegurar que todas las pruebas pasen y se alcance el nivel de cobertura adecuado.

3. **Construcción:**
   - Escribir un Dockerfile para el frontend y construir la imagen.
   - Etiquetar la imagen con la versión `v1.0.0-practica`.
   - Subir la imagen a la cuenta de Docker Hub del estudiante.

   - Crear un workflow de CI (GitHub Actions) para el repositorio del frontend.
   - Configurar el workflow para ejecutar las pruebas unitarias en cada `push` al branch principal (tomar como referencia el laboratorio [04. Automatización de Pruebas Unitarias](./04.%20Automatizacion%20de%20Pruebas%20Unitarias.md)).


5. **Análisis de Código y Vulnerabilidades (CVE):**
   - Integrar SonarCloud en el workflow para analizar la calidad del código del frontend.
   - Integrar Snyk en el workflow para analizar las dependencias del frontend.
   - Configurar el escáner para que falle el workflow si detecta vulnerabilidades con severidad `CRITICAL`.
   - Exportar los resultados del análisis como artefactos.

6. **Investigar sobre el escaneo de vulnerabilidades en contenedores**
	- Agrega un paso en el workflow para construir la imagen de Docker.
	- Agrega un paso en el workflow para etiquetar la imagen de Docker.
			Ejemplo: `[DOCKER_HUB_USER]/frontend-practica:v1.0.0`
	- Agrega un paso en el workflow para subir la imagen de Docker a Docker Hub.
	- Agrega un paso en el workflow para escanear la imagen de Docker usando Trivy.
```yaml
- name: Escanear imagen de Docker con Trivy
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: '[IMAGE_NAME]:[VERSION]'
    format: 'table'
    exit-code: '1'
    severity: 'CRITICAL,HIGH'
```
El flag `exit-code: '1'` provocará que el flujo falle si encuentra vulnerabilidades de alta severidad.
